# 도덕 AI 도우미 — 배포 가이드

## 구조
```
/index.html        학생·교사가 보는 화면 전체
/prompts.json       AI에게 보내는 지침(문구) — 이 파일만 고쳐도 챗봇 말투/규칙이 바뀝니다
/api/create-room.js 교사가 API 키를 등록하면 방 코드를 발급하는 서버 함수
/api/chat.js         방 코드로 교사의 키를 찾아 Claude(Anthropic)를 대신 호출하는 서버 함수
/api/_anthropic.js   Claude 호출 공통 모듈(모델 대체 순서, 아동 안전 시스템 지시) — 공개 주소 없음
/api/_privacy.js     AI로 보내기 직전 개인정보 이중 확인 — 공개 주소 없음
```

학생 브라우저는 절대 실제 API 키를 보지 않습니다. 방 코드만 오갈 뿐, 진짜 키는 서버(정확히는 Upstash Redis 저장소)에만 있습니다.

## 처음 배포하는 방법 (한 번만 하면 됩니다)

### 1. GitHub에 코드 올리기
1. [github.com](https://github.com)에서 새 저장소(Repository)를 만듭니다 (Private으로 해도 됩니다).
2. 이 폴더 안의 파일들(`index.html`, `prompts.json`, `api/` 폴더)을 그대로 업로드합니다.

### 2. Vercel 계정 만들고 연결하기
1. [vercel.com](https://vercel.com)에서 GitHub 계정으로 가입합니다.
2. "Add New... → Project"에서 방금 만든 저장소를 선택하고 **Deploy**를 누릅니다.
3. 별다른 설정 없이 그대로 배포하면 됩니다(정적 파일 + `/api` 폴더를 Vercel이 자동으로 인식합니다).

### 3. 저장소(Upstash Redis) 연결하기 — 방 코드를 저장할 공간
1. 방금 만든 Vercel 프로젝트 화면에서 **Storage** 탭 → **Marketplace Database Providers** → **Upstash**를 선택합니다.
2. Redis 데이터베이스를 무료 플랜으로 생성하고, 지금 만든 프로젝트에 연결(Connect)합니다.
3. 연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN` 같은 환경변수가 프로젝트에 **자동으로 추가**됩니다 — 따로 값을 입력하실 필요는 없습니다. (연결할 때 접두사를 바꿔 `UPSTASH_REDIS_REST_URL`, `STORAGE_KV_REST_API_URL` 같은 이름이 되어도 코드가 알아서 찾습니다.)
4. 환경변수가 추가된 뒤에는 **Deployments** 탭에서 최신 배포를 한 번 "Redeploy" 해주세요(환경변수는 재배포해야 적용됩니다).

### 4. 완료
이제 Vercel이 알려주는 주소(예: `https://당신의프로젝트.vercel.app`)가 실제 서비스 주소입니다. 이 링크를 선생님들께 공유하시면 됩니다.

## 이후 사용 흐름

1. **선생님**: 위 주소로 접속 → Claude API 키 입력 → "방 만들기" → **수업 설정**에서 탐구할 덕목을 고름 → 학생용 공유 링크·QR 코드가 뜸 → "확인, 테스트해볼게요"를 눌러 직접 사용해봄.
   - 목록의 덕목(3~6학년 교과서 덕목 19개)은 지도서의 학년으로 고정되어, 학년을 따로 고르지 않습니다.
   - 목록에 없는 덕목은 "직접 입력"을 골라 덕목 이름과 학년을 정합니다.
   - 덕목(직접 입력이면 학년까지)을 정하기 전에는 링크·QR이 만들어지지 않습니다.
2. **학생**: 선생님이 공유한 링크(또는 QR)로 접속 → 키 입력 없이, 선생님이 정한 덕목으로 바로 시작합니다. 학생이 덕목을 직접 입력하는 단계는 없습니다. 덕목 정보가 없는 링크로 들어오면 "선생님께 새 수업 링크를 받아 주세요"라는 안내만 나옵니다.
3. 수업마다 덕목을 바꾸려면 화면 위 🔗 버튼 → 수업 설정 변경 → 새 링크·QR을 학생에게 공유하면 됩니다. 같은 방(API 키)으로 여러 덕목의 링크를 만들 수 있습니다. 설정을 바꾼 뒤 "확인"을 누르면 선생님 화면의 대화도 새 설정으로 다시 시작됩니다.
4. 3~4학년 수업(3~4학년 덕목, 또는 직접 입력한 덕목에 3~4학년을 고른 경우)은 활동3의 소크라테스식 질문을 1개만 하고 바로 가상 상황으로 넘어갑니다.
5. 방은 **48시간** 동안 유효합니다. 그 이후엔 선생님이 다시 방을 만들어야 합니다(같은 키를 다시 입력하면 새 방이 만들어집니다).

## Claude API 키는 어디서 받나요?

1. [Claude Console 키 발급 안내](https://platform.claude.com/docs/en/get-api-key)에 따라 Console에 가입하고 API 키를 만듭니다(`sk-ant-`로 시작).
2. **Console의 결제(Billing) 화면에서 크레딧을 먼저 충전해야 합니다.** Claude API에는 무료 사용량이 없어서, 크레딧이 없으면 방 만들기 단계에서 "크레딧이 없어요" 안내가 뜹니다.
3. 혹시 모를 오남용에 대비해 Console에서 월 사용 한도(spend limit)를 낮게 걸어 두시길 권장합니다.

### 비용 (대략)

기본 모델은 Claude Haiku 4.5입니다(입력 100만 토큰당 $1, 출력 100만 토큰당 $5 — 가격은 바뀔 수 있으니 Anthropic 요금 페이지에서 확인해 주세요). 이야기 생성과 사례 검수를 합쳐 학생 1명이 활동1~3을 한 번 끝까지 하면 약 $0.03(40원 안팎)입니다. 23명 × 5회 수업이면 약 $3~5 정도로 예상합니다.

## 앞으로 수정할 때

- **문구·지침만 바꾸고 싶다면**: `prompts.json`만 고쳐서 GitHub에 올리면 끝입니다.
- **화면·로직을 바꾸고 싶다면**: `index.html` 또는 `/api` 안의 파일을 고쳐서 올립니다.
- GitHub에 올리기만 하면 Vercel이 1분 안에 자동으로 재배포합니다. 이미 발급된 학생 방 코드는 재배포해도 사라지지 않습니다(저장소와 코드는 분리되어 있습니다).

## 서버 키 모드 (교사가 API 키를 입력하지 않는 방식)

Vercel 환경변수에 운영자의 Claude API 키를 넣어 두면, 교사는 키를 입력하지 않고 방을 만들 수 있습니다. 수업 시연처럼 한 사람의 키로 운영할 때 씁니다.

**켜는 방법 (Vercel → 프로젝트 → Settings → Environment Variables)**

| 이름 | 값 | 필수 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 운영자의 Claude API 키(`sk-ant-...`) | 필수 |
| `TEACHER_CODE` | 방을 만들 때 입력할 교사 코드(예: `도덕2026`) | 권장 |
| `ROOM_CALL_LIMIT` | 방 하나에서 쓸 수 있는 AI 호출 횟수(기본 6000) | 선택 |

저장한 뒤 **Deployments → 최신 배포 → Redeploy**를 해야 적용됩니다.

**동작**
- 첫 화면에서 API 키 칸이 사라지고, 교사 코드(정해 둔 경우)만 입력하면 방이 만들어집니다. 이후 덕목 선택·학생 링크·QR은 같습니다.
- 키는 환경변수에만 있습니다. 저장소(Upstash)에는 "서버 키로 만든 방"이라는 표시만 저장되고, 학생·교사 화면으로는 키가 전달되지 않습니다.
- `TEACHER_CODE`를 정하지 않으면 사이트 주소를 아는 누구나 방을 만들어 운영자 크레딧을 쓸 수 있으므로, 꼭 정해 두는 것을 권장합니다.
- 방 하나의 AI 호출이 `ROOM_CALL_LIMIT`을 넘으면 그 방은 멈추고 "새 방을 만들어 주세요" 안내가 나옵니다(한 학급 2시간 수업은 보통 1,500회 안팎).

**끄는 방법 (다시 교사가 키를 입력하는 방식으로)**
- `ANTHROPIC_API_KEY` 환경변수를 지우고 Redeploy하면, 코드 수정 없이 기존의 "API 키 입력 → 방 만들기" 화면으로 돌아갑니다.
- 서버 키로 만들어 둔 방은 그때부터 작동하지 않습니다(교사가 자기 키로 새 방을 만들어야 함).

## 대화 저장하기 (평가용 대화 기록)

- 화면 위 머리글의 **대화 저장하기** 버튼은 활동3이 끝나고 마지막 안내까지 나온 뒤에 켜집니다(그 전에는 흐리게 표시되어 눌리지 않음).
- 누르면 그 학생 기기에 `도덕AI도우미_덕목_대화기록_날짜_시각.txt` 파일이 저장됩니다. 서버에는 저장되지 않습니다.
- 파일에는 탐구한 덕목, 처음 정리한 뜻과 다시 정리한 뜻, 활동1~3의 대화 전체(사례, 탐구 질문, 학생의 답, 가상 상황과 판단·이유, 활동지 안내)가 시간 순서대로 들어갑니다. "이전 답 다시 쓰기"로 지운 답은 들어가지 않습니다.
- 학생 이름은 파일에 들어가지 않습니다. 누구의 파일인지는 제출 방법(학급 플랫폼의 학생별 제출함 등)으로 구분해 주세요.
- 대화 초기화를 누르거나 창을 닫으면 대화가 사라지므로, 저장은 그 전에 해야 합니다.

## 학생 개인정보 보호와 안전장치

**AI로 보내지는 글:** 학생이 쓴 글 중 활동2 마지막의 "다시 정리한 뜻"과 활동3 질문에 대한 답만 AI 회사(Anthropic) 서버로 보내집니다. 활동1 답, 첫 번째 뜻, 활동3 판단 이유는 학생 기기 밖으로 나가지 않습니다. 우리 서버(Vercel)는 글을 저장하지 않고 전달만 합니다.

**자동으로 하는 일**
- **입력 확인(학생 기기에서):** 모든 입력창에서 보내기 전에 확인하고, 걸리면 보내지 않고 안내만 띄웁니다(글은 입력창에 남아 고칠 수 있음).
  - 개인정보: 전화번호, 이메일, 주민등록번호, 긴 숫자(계좌번호 등), 주소(동·호수, 시·구·동, 도로명), 학년·반·번호, 학교 이름+학년, "제 이름은 ○○", SNS 아이디
  - 욕설·비속어(띄어쓰기로 피해도 확인)
  - 의미 없는 답: 숫자·기호만(123, ???), 자음·모음만(ㅋㅋㅋ, ㅁㄴㅇㄹ), 자판 두드리기(asdf), 한 글자, 같은 글자 반복, "그냥·네·없어요" 같은 말만 쓴 답, "몰라요"만 쓴 답(헷갈리는 점을 써 보도록 안내). 3번 연속 막히면 선생님께 도움을 요청하도록 안내합니다. 문장으로 쓴 답은 내용과 상관없이 통과시킵니다(AI가 아닌 규칙으로만 판단해, 뜻이 통하는 짧은 답을 잘못 막지 않기 위함).
  - 도움이 필요할 수 있는 표현(자해·자살·학대 관련): 선생님이나 믿을 수 있는 어른에게 말하도록 안내합니다.
- **서버 이중 확인:** AI로 보내기 직전에 전화번호·이메일·주민등록번호를 한 번 더 확인합니다.
- **아동 안전 시스템 지시:** 서버가 모든 AI 요청에 "초등학생 대상, 안전하지 않은 내용 금지, 개인정보를 묻거나 지어내지 않음, 사람인 척하지 않음" 지시를 붙입니다. 학생 화면에서 요청 내용을 바꿔 보내도 이 지시는 빠지지 않습니다.
- **개인정보 약속 안내:** 시작할 때 "이름, 전화번호, 주소 같은 개인정보는 쓰지 않기로 해요"를 안내하고, 뜻 정리·활동3 입력창에도 "(개인정보는 쓰지 않아요)"를 표시합니다.

**자동으로 못 하는 일:** 학생·친구·가족의 **이름**은 보통 낱말과 구별하기 어려워 자동으로 다 걸러지지 않습니다. 수업 전에 "이름·개인정보는 쓰지 않기"를 꼭 안내해 주세요.

**학교 적용 전 확인:** 학생의 글이 외부 AI 서비스로 전송되므로, 학교에서 사용하기 전에 교육부 「학습지원 소프트웨어 선정 기준」에 따른 학교 절차(학교운영위원회 심의 등) 대상인지 학교에 확인해 주세요.

## 덕목 프로필 (초등 도덕 교사용 지도서 기준)

`prompts.json`의 `virtueProfiles`에 3~6학년 교과서 단원의 덕목 19개가 등록되어 있습니다.

- **지도서 원문 그대로:** `definition`(정의), `grade`(학년), `unit`(단원), `guidance`(지도상 유의점 — 현재 효에 입력됨)
- **원문에서 문구를 그대로 발췌:** `attributes`(정의적 속성) — 사례 유형(전형/반대/관련/경계)을 나누고 판정하는 기준으로 쓰입니다.
- **초안(교사 검토 필요):** `relatedConcepts`(헷갈리기 쉬운 개념 — 관련 사례에 사용), `contexts`(활동2 관계 선택지), `scope`, `notes`, `extraFailChecks`(그 덕목에만 더하는 실패 조건, 예: 효의 '무조건적인 복종·순종을 바람직한 효로 그림')

이야기의 학년 수준은 프로필의 학년에 맞춥니다. 교사가 "직접 입력"한 덕목은 지도서 정의 없이 AI가 일반적인 뜻으로 사례를 만들고, 교사가 고른 학년 수준에 맞춥니다.

## 사례 자동 검수 (판정 AI)

학생에게 보여주는 모든 이야기(활동1 사례 4종, 활동2 관계 속 이야기, 활동3 가상 상황)는 화면에 나가기 전에 한 번 더 검사를 거칩니다.

1. 이야기를 생성하고, 앞뒤에 붙은 표시(예: "개념: 동정심", "[관련 사례]", "이야기:")를 떼어 냅니다.
2. **규칙 검사(코드):** 글자만 보고 확실히 알 수 있는 문제를 먼저 거릅니다 — 사례 유형·개념 이름 표시가 본문에 섞임, 활동1 사례에 덕목 이름(예: "인류애")이나 관련 사례의 개념 이름(예: "동정심")을 직접 씀, 서술자가 "~하기보다는"처럼 더 나은 행동과 비교하거나 "옳은 일이었다"처럼 판정함. 걸리면 판정 AI를 부르지 않고 바로 다시 쓰게 하며, 이 경우 다시 쓸 기회를 한 번 더 줍니다.
3. **판정 AI:** 그 이야기가 용도(전형/반대/관련/경계 사례, 관계 맥락, 가상 상황 방향)의 기준에 맞는지 판정합니다.
4. 탈락하면 탈락 사유와 탈락한 초안을 알려주고 새로 씁니다.
5. 끝까지 탈락하면, 규칙 검사를 통과한 가장 최근 초안을 보여줍니다(수업이 멈추지 않도록).

- 실패 조건은 `prompts.json`의 `commonChecks`(모든 이야기 공통), `caseTypes.*.failChecks`(사례 유형별), `situationChecks`·`contextChecks`(활동2), `counterChecks`(활동3)에 있습니다. **이야기를 만드는 AI의 최종 점검과 판정 AI의 기준이 이 같은 목록에서 나오므로**, 한 곳만 고치면 양쪽에 함께 반영됩니다.
- 판정 AI 호출이 실패하면 수업이 막히지 않도록 통과로 처리합니다.
- 활동1에서는 학생이 사례를 읽는 동안 다음 사례를 미리 생성·검수해 두므로 대기 시간이 거의 늘지 않습니다. 활동2·3은 판정 1회만큼(보통 1~2초) 대기가 늘어납니다.
- 검수 과정은 브라우저 개발자 도구(F12 → Console)에 `[사례 검수]`로 기록됩니다.

- API 키는 서버에만 저장되고 학생 화면에는 노출되지 않습니다.
